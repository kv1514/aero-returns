# Working on AERO

This is a standalone React/Vinext and Cloudflare D1 demo. Read `README.md` for local setup and `docs/HANDOFF.md` for current status. Do not modify the unrelated parent arbitrage engine when working in the original nested checkout.

## Behavior contracts

- Returns are simulated by default: the drone fleet, participating hubs, price estimates and handoffs are demo configurations. No payments, refunds, or retailer return authorizations are implemented.
- Nothing is booked when a person opens the app; a return exists only after they tap Request. The server assigns the simulated drone (the nearest one not busy on that owner's other active simulated returns); the browser never chooses it.
- A real PX4/ArduPilot drone can fly a return only through the drone link (`docs/DRONE_LINK.md`): owner-registered drone, signed commands, operator checklist arming, geofence and 120 m cap, operator-launched takeoffs, always-available abort. Never let the simulator silently switch to real flight, never let a customer action launch a drone, and never weaken these gates to make a demo smoother.
- Pickup at a customer's pin is opt-in per drone. A live flight goes to the pin only when the drone has a pin zone (`pinRadius`, 0–100 m around the surveyed pickup pad, default 0 = off) and the pin lies inside it and at least `PIN_MARGIN_M` (15 m) inside the geofence (`pickupFor` in `lib/drone-mission.ts`); otherwise it uses the pickup pad, which stays required. At a pin the drone hovers (`HOVER_PICKUP`) and lands only on the operator's "Landing area clear · land" while its fresh report puts it over the pin (`atPin`). Dispatch flies only the pickup Fleet previewed (`pickupMismatch`, 409 when it changed). Never let a pin outside these checks become a flight target, never send a LAND at a pin that the operator did not ask for, and keep the bridge's own fence check, with `--fence-center`/`--fence-radius` equal to Fleet's home and geofence radius.
- Person hold: a return whose Claude check is `needs_person`, or a `not_drone_eligible` check stamped by `bookedReview` at booking, stays on the ground, simulated or live, until a person approves or declines it (`heldForPerson` in `lib/simulation.ts`). Demo controls, the simulator and Fleet dispatch cannot bypass it, and it never applies retroactively to unstamped checks.
- Preserve explicit package-loading confirmation. Advancing the simulation cannot bypass it.
- Claude features send photos and notes only after the user's click. AERO stores the decision summary or a usage event, never the photos. A booking attaches a Claude check only from the owner's own stored event, never from browser input.
- Real Google Places listings are discovery results, not verified participating drone facilities or proof of QR acceptance. Keep them separate from simulated hub routing.
- Location is opt-in and one-shot. Never add background tracking by default. Keep real booking pickup inside the demo service boundary.
- The legacy Login with Amazon connection links a profile only; Supabase custom Amazon sign-in authenticates an AERO account. Standard profile scopes do not supply purchase history or create returns. Do not scrape signed-in accounts or collect Amazon passwords. Keep tokens out of persistence and logs.
- Scope every stored return, drone and linked account to its owner. The public Worker has no access gate, so owner scoping is the protection. For Supabase accounts, authorize only using server-verified `getUser()` IDs, never user metadata or an unverified cookie. Preserve origin checks, OAuth state/PKCE, and atomic version checks. The earlier ChatGPT Sites prototype keeps its private gate.
- Keep API secrets in ignored `.dev.vars` or Worker secrets (`docs/DEPLOY.md`). A standard Google browser key must be website/API restricted; it is intentionally public to browsers. The owner-approved no-billing Maps Demo Key used on the Sites prototype is an exception: Google limits its APIs and quota, and gates custom key settings behind an upgrade. Never attach billing or upgrade it automatically.
- The home-screen app has no service worker: tracking, telemetry and API answers always come from the network. Do not add offline caching of live state. Keep `SPLASH` in `app/layout.tsx` and `scripts/generate-pwa-assets.mjs` in step (`npm run pwa:assets`).
- Internal links are plain `<a href>`, never `next/link`: with vinext 1.0.0-beta.5 a `<Link>` click throws and the page does not navigate (`tests/plain-links.test.ts`).
- Do not claim sponsor qualification, live integration verification or a physical flight without actual evidence. `/demo` and `data/hackathon-tracks.json` document the researched tracks and their limits.

## Validation and publishing

Use Node 24 (minimum 22.13), `npm ci`, `npm run typecheck`, `npm test`, `python3 -I bridge/test_bridge.py`, `python3 tests/test_product_actor.py`, and `npm run build`; CI runs the same. Lint the files you change with `node_modules/.bin/eslint <files>` (`npm run lint` still reports three older errors, so CI does not lint). With the local database migrated (all of `drizzle/0000`–`0004`) and the dev server running, run `node_modules/.bin/tsx scripts/smoke.ts <baseUrl>`, `scripts/location-account-smoke.ts <baseUrl>` and `scripts/demo-account-smoke.ts <baseUrl>`. These tests do not call paid providers.

The public deployment is the Cloudflare Worker `aero-returns` (https://aero-returns.kv15.workers.dev) with D1 database `aero-returns`; deploy with `npm run deploy` after `wrangler login` (see `docs/DEPLOY.md`). GitHub pushes alone do not deploy. The original ChatGPT Sites prototype is owner-private; preserve `.openai/hosting.json`, and set `AERO_TRUST_SITES_IDENTITY=true` only behind the Sites proxy, because elsewhere any client can forge the `oai-authenticated-user-*` headers. Report local build completion separately from hosted deployment.

For drone link changes also run `node_modules/.bin/tsx scripts/drone-link-smoke.ts <baseUrl>` plus `node_modules/.bin/tsx scripts/bridge-e2e.ts <baseUrl>` (real bridge, simulated vehicle) against a running app; local runs need `DRONE_LINK_SECRET` in `.dev.vars`.
